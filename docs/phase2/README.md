# Phase2 Design and Current Status

Japanese version: [README.ja.md](README.ja.md)

Phase2 is Clove's experimental native-build path. The existing runtime remains responsible for the REPL and script execution, while `clove build` now sends a supported subset of the language through a C backend.

## Runtime and build paths

| Path | Purpose | Main components | Current entry point |
| --- | --- | --- | --- |
| Phase1 runtime path | Flexible REPL and script execution, including dynamic language features | [`clove-core`](../../crates/clove-core/), [`clove-lang`](../../crates/clove-lang/), [`clove-lsp`](../../crates/clove-lsp/) | `clove --repl`, `clove file.clv` |
| Phase2 native build path | Ahead-of-time compilation of a statically supported subset | [`clove-build-front`](../../crates/clove-build-front/), [`clove-build-backend-c`](../../crates/clove-build-backend-c/), [`clove-build-runtime-c`](../../crates/clove-build-runtime-c/) | `clove build file.clv` |

The current native build flow is:

```text
Clove source
  -> clove-build-front
  -> C source generated by clove-build-backend-c
  -> system C compiler
  -> native executable
```

[`clove-build-core`](../../crates/clove-build-core/) contains the Phase2 parser, type, code-generation, and VM infrastructure developed during the redesign. The current C path reuses its syntax model but does not yet expose every Phase2 design feature through `clove build`.

## Design direction

- **Native-first build path:** unsupported dynamic behavior is rejected during native compilation instead of silently falling back to the interpreter.
- **Type-informed lowering:** the longer-term direction is a shared typed pipeline for build, runtime optimization, and LSP diagnostics. That unification is still in progress.
- **Explicit foreign boundaries:** native builds are designed to keep external-language calls visible rather than treating them as ordinary dynamic values.
- **Limited dynamic values:** `Any` is avoided where possible, and `Dyn` is intended for explicit boundaries.

### `mut` and `imut`

Phase2 distinguishes two collection-update modes:

- `imut` preserves the observable original value.
- `mut` requires an in-place update and rejects the operation when the value is shared.

This distinction is part of the Phase2 compiler design and is implemented in `clove-build-core`. The integrated C backend does not yet expose `--mut`, `--mode`, or `--native` options, so these modes should not be read as current `clove build` command-line guarantees.

## Current implementation status

- `clove build` is wired to the C backend and produces a native executable for the supported subset.
- `--out` / `--output` selects the executable path; `--emit-c` keeps and prints the generated C path.
- REPL and ordinary script execution continue to use the existing runtime.
- `clove-lsp` provides editor-facing language support independently of the native build path.
- In the current C backend, `upper-case`, `lower-case`, and `capitalize` accept ASCII strings only. A native executable reports an explicit runtime error for non-ASCII input instead of producing invalid UTF-8.
- The C backend is experimental. Not every example accepted by the interpreter is buildable yet.

## Build example

Install the CLI from a clone:

```bash
cargo install --path crates/clove-lang
```

Build and run the checked example:

```bash
clove build examples/build/high_value_report.clv \
  --out target/clove/bin/high_value_report
./target/clove/bin/high_value_report
```

To inspect the generated C file:

```bash
clove build examples/build/high_value_report.clv \
  --out target/clove/bin/high_value_report \
  --emit-c
```

A working system C compiler is required.

## Historical benchmark

The [2026-01-29 benchmark record](bench/records/bench_release_20260129.md) compares the earlier `clove2` native build and VM path with Rust, Go, Ruby, and Clojure on the same workload.

| Implementation | hyperfine mean | max RSS |
| --- | ---: | ---: |
| `clove2` generated executable | 0.3626 s | 5.3 MiB |
| `clove2 run(vm)` | 1.429 s | 280.0 MiB |
| Rust | 0.1299 s | 2.7 MiB |
| Go | 0.2000 s | 9.3 MiB |
| Ruby | 1.150 s | 57.4 MiB |
| Clojure | 1.289 s | 600.5 MiB |

These measurements predate the integrated C backend and are retained as a historical baseline, not as a performance claim for the current `clove build` implementation. The record contains the commands, run counts, and raw `hyperfine` output.
