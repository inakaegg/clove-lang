# 型は任意注釈にとどめる

English version: [gradual-typing.md](gradual-typing.md)

- 更新日: 2026-07-25

## 決定

型注釈は**任意**です。書いても書かなくても動きます。そして
**実行時の型検査には使いません**。

```clojure
(defn add [x y] (+ x y))              ; 注釈なし
(defn add :int [x<Int> y<Int>] (+ x y)) ; 戻り値と引数に注釈
```

注釈があっても、境界で型が検査されるわけではありません。

```bash
clove -e '(defn add :int [x<Int> y<Int>] (+ x y)) (println (add "a" "b"))'
# Type mismatch: expected number (arg 1 to +), got str ("a")
```

エラーは `+` の中で出ています。`add` の引数を受け取った時点ではなく、
実際に数値が要求された場所です。注釈は「ここは Int のはず」という**宣言**であって、
関門ではありません。

## 理由

型情報は主に3つの用途のために持っています。

**LSP。** 補完候補の絞り込み、ホバーでのシグネチャ表示、inlay hint。
注釈があるほど精度が上がります。

**[ネイティブビルドの最適化](two-phase-implementation.ja.md)。** ビルド経路では
HM 型推論を行い、型が確定した箇所を特化したコードに落とします。これが
`clove build` の性能上の主要な手段です。

**読み手への情報。** 関数の意図を書く手段として。

いずれも「書いたら得をする」性質のもので、「書かないと動かない」必要はありません。
実行時検査を入れると、注釈を書くことが**コスト**になります。動的に書き始めて、
固まったところから注釈を足していける方が、この言語の使われ方に合っています。

## 採らなかった案

**注釈を実行時に検査する。** 「宣言したのだから守らせる」案です。外しました。
検査のコストが常にかかるうえ、注釈を足すたびに既存コードが壊れる可能性が出ます。
注釈は後から足せるものであってほしいので、足しても挙動が変わらない方を選びました。

**型を必須にする。** 全体の最適化と安全性は上がりますが、REPL で気軽に書けなくなります。
Clove は REPL とスクリプト実行を主要な使い方として想定しています。

**型を持たない。** LSP の精度とネイティブ最適化の両方を諦めることになります。

## 記法

型注釈は2つの位置に書けます。

```clojure
(def x<Int> 10)              ; シンボルへの後置
(def v [1 2]: [Int Int])     ; 式への後置
(def m: Map<Str, Int> {"a" 1}) ; ジェネリクスはカンマ区切り
```

後置の `<...>` を選んだのは、S式の構造を壊さないためです。前置や別の位置に置くと
リーダーとフォーマッタの両方で特別扱いが増えます。詳細と対応する型の一覧は
[型ヒント](../language/type_hints.ja.md) にあります。

## 段階的な性質

型が「ヒント」であることは、次の3段階が同じコードで成立することを意味します。

1. 注釈なしで書いて REPL で動かす
2. 固まった関数に注釈を足す。挙動は変わらない
3. `clove build` で注釈を最適化に使う。ここで初めて型が厳密に扱われる

3 の段階では型が合わないとビルドが通りません。つまり**厳密な検査はネイティブビルドに
寄せてある**、という設計です。インタプリタでは緩く、ビルドでは厳しく。

```bash
clove build app.clv    # (defn add [x<Int> y<Int>] (+ x y)) に (add "a" "b")
# expected Int expression
```

注釈がなくても推論が効く範囲では同じく落ちます。注釈は推論を助けるものであって、
検査の有無を切り替えるスイッチではありません。

> ネイティブビルド側は現時点で**戻り値の注釈（`(defn add :int [...])`）を受け付けません**
> （`syntax error: params must be a vector`）。引数の後置注釈は使えます。
> ネイティブ経路の対応範囲は[インタプリタとネイティブビルドの2経路](two-phase-implementation.ja.md)
> を参照してください。
